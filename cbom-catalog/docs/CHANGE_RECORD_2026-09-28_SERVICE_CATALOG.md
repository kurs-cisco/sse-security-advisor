# Service Catalog change record — 2026-09-28

## Product behavior

- The primary navigation calls the former Accountability page **Service Catalog**. `/accountability` redirects to `/service-catalog` and preserves a `group` deep link.
- The table shows each `(source_collection, service_group)` once, with the service display name, owner and lead, optional linked user profiles, IL2 and IL5 planning status and target date, service-impact risk, comments, additional display attributes, and publication state. Existing imported planning and service-impact records remain the initial Admin view.
- An Admin can add a service group as a managed control-plane record and directly publish managed metadata changes. A new group has no synthetic CBOM evidence or source routing. It needs an exact Admin group-to-service mapping before service roles can reach it.
- A Product Lead can submit a change proposal only for an exact granted service group. IL2 changes require its Government lead grant; IL5 changes require its Defense lead grant. A separate Admin approves or rejects it with a reason. Product Engineers have read-only catalog access. Summary users cannot enumerate the catalog.
- Managed records have optimistic revisions, immutable revision snapshots, append-only proposals and decisions, an audit event per write, and a database trigger that prevents a proposal submitter from deciding that proposal. An explicit override mask lets an approved change clear an imported owner, lead, risk, comment, or target date while untouched fields still inherit the import. Optional owner and lead profile emails resolve to active application users; profile links do not create access grants.
- The existing evidence drawer is available to Admins for services with current source files. It is rendered outside the inert page layer so its close button works. Control-plane-only groups do not open an evidence drawer.

## Data boundary

Migrations 022–024 create operational `app_auth` tables, revisions, approval controls, and the override mask. They do not rewrite `source_file`, `service_group`, Team Tracker, service-impact, assessment, or POA&M source records. The source-group slug remains an immutable identity for scope checks and fingerprints; the managed display name is editable.

Product roles see only their exact `(source_collection, service_group)` rows. The reviewed Team Tracker mapping is explicitly tied to `sse-cboms`, so its imported owner, lead, and IL2/IL5 planning baseline appears for an exact SSE grant. A same-named group in another collection cannot inherit that baseline. Imported service-impact risk and comments follow their own exact collection/group key. Managed values take precedence after approval, including explicit clears. The IL2/IL5 plans are operational assertions, not authorization, FedRAMP, CMVP, or FIPS validation evidence.
